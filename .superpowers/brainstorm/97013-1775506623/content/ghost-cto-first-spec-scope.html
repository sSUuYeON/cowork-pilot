Ghost CTO 첫 번째 Spec 범위

무엇을 먼저 고정할지 정해야 planning 엔진 spec도 정확해집니다.

추천 방향

추천: B안

핵심 워크플로는 깊게 정의하고, planning/kanban은 "연동 계약"까지만 같이 고정합니다.

A

좁게

요구사항 제출, AI 평가, 운영 승인/거절, spec version 갱신까지만 정의

장점

  • 문서가 가장 작고 빠르게 합의됨
  • 도메인 모델에만 집중 가능

단점

  • planning/kanban 연결부를 나중에 다시 뜯을 가능성 큼
B

중간안

핵심 워크플로는 깊게 정의하고, planning 시작 조건과 칸반 상태 생성 규약만 같이 정의

장점

  • 도메인 spec이 planning spec의 상위 문서가 됨
  • 나중에 엔진 개선 시 계약이 흔들리지 않음

단점

  • 좁은 문서보다 약간 무거움
C

넓게

핵심 워크플로, planning 알고리즘, 칸반 UI/운영 화면까지 한 번에 정의

장점

  • 한 문서에서 전체 그림을 볼 수 있음

단점

  • 너무 커져서 첫 spec 합의가 느려짐
  • 애매한 문구가 늘어날 가능성이 큼

카드를 클릭해서 선택해도 되고, 터미널에 A/B/C 또는 의견을 바로 적어도 됩니다.
